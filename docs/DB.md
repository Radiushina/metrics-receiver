# Работа с PostgreSQL: установка, базы, таблицы, драйвер

Документ описывает полный сценарий: убедиться, что PostgreSQL установлен и запущен, создать базу и пользователя, выдать права, переключаться между базами, смотреть таблицы и понимать, как приложение подключается к СУБД через **драйвер**.

---

## 1. Термины: что с чем связано

| Понятие | Кратко |
|--------|--------|
| **Сервер PostgreSQL (кластер)** | Один запущенный процесс, который слушает порт (часто `5432`) и обслуживает **много отдельных баз данных**. |
| **База данных (database)** | Изолированное «пространство» внутри кластера: свои таблицы, схемы, права. База `postgres` — служебная, к ней удобно подключаться для админских задач. |
| **Схема (schema)** | Папка внутри базы. По умолчанию пользовательские таблицы часто лежат в схеме **`public`**. |
| **Таблица** | Данные в виде строк и колонок; принадлежат конкретной **базе** и **схеме**. |
| **Роль / пользователь** | В PostgreSQL пользователь = роль с правом входа (`LOGIN`). Имя роли и имя базы **могут совпадать** — это разные сущности. |
| **Драйвер** | Библиотека в языке программирования (например Go: `github.com/jackc/pgx`, `database/sql` + драйвер PostgreSQL), которая умеет по сети говорить с сервером по протоколу PostgreSQL. Приложение **не** вызывает `psql` — оно использует драйвер и **строку подключения** (хост, порт, имя базы, пользователь, пароль, иногда SSL). |

Итог: **таблицы «на компе» существуют внутри конкретной базы**. Список таблиц зависит от того, **к какой базе вы сейчас подключены**.

## 2. Проверить, установлен ли PostgreSQL (macOS, Homebrew)

```bash
which psql
psql --version
```

Если `psql` найден — клиент установлен. Сервер — отдельно: его нужно **запустить** (см. ниже).

Проверка пакетов Homebrew:

```bash
brew list --versions postgresql@17
```

(версия `@16`, `@15` и т.д. может отличаться).

---

## 3. Запуск и остановка сервера (Homebrew)

Список сервисов:

```bash
brew services list | grep -i postgres
```

- Статус **`none`** (или не `started`) — сервер **не** запущен как фоновый сервис.

Запуск (подставьте свою версию, например `postgresql@17`):

```bash
brew services start postgresql@17
```

Остановка:

```bash
brew services stop postgresql@17
```

Если при подключении ошибка **`Connection refused`** — сервер не слушает порт: сначала `brew services start ...`.

## 4. Подключение через `psql`

Интерактивный клиент командной строки — **`psql`**. Он подключается к **указанной базе** от имени **указанного пользователя**.

Частый первый вход в служебную базу `postgres`:

```bash
psql -d postgres
```

Явно указать хост, порт, пользователя:

```bash
psql -h localhost -p 5432 -U имя_пользователя -d postgres
```

Часто локальный пользователь ОС совпадает с суперпользователем в Postgres (у вас встречался пользователь `developer`). Узнать имя в терминале:

```bash
whoami
```

## 5. Как понять, к какой базе вы подключены

Смотрите на **приглашение** в `psql`:

| Приглашение | Значение |
|---------------|----------|
| `postgres=#` | Вы в базе **`postgres`**, режим суперпользователя (часто `#`). |
| `videos=#` | Вы в базе **`videos`**. |
| `dbname=>` | Обычный пользователь без прав суперпользователя (часто `=>`). |

Проверка без угадывания:

```sql
SELECT current_database(), current_user;
```

или метакоманда:

```text
\conninfo
```

## 6. Список баз и переключение между ними

Список всех баз:

```sql
\l
```

Переключиться на другую базу **в том же сеансе**:

```sql
\c имя_базы
```

Пример:

```sql
\c videos
\c postgres
```

Важно: команда **`\dt`** показывает таблицы **только текущей базы**. Если вы в `postgres`, вы увидите таблицы базы `postgres`; база `videos` при этом может быть пустой — это нормально.

---

## 7. Таблицы: посмотреть и понять «пустую» базу

Внутри нужной базы (`\c нужная_база`):

```sql
\dt
```

- Сообщение вроде **«Отношения не найдены»** значит: в этой базе **ещё нет таблиц** в схеме по умолчанию (часто `public`).

Структура конкретной таблицы:

```sql
\d имя_таблицы
```

Создание простой таблицы (пример):

```sql
CREATE TABLE videos (
  id          bigserial PRIMARY KEY,
  title       text NOT NULL,
  created_at  timestamptz NOT NULL DEFAULT now()
);
```

Снова `\dt` — таблица должна появиться.

## 8. Создание новой базы и пользователя, права

### 8.1. Рекомендуемый порядок (пользователь сразу владелец базы)

Выполняйте из-под администратора (часто подключение к `postgres`):

```sql
CREATE USER имя_пользователя WITH PASSWORD 'надёжный_пароль';
CREATE DATABASE имя_базы OWNER имя_пользователя;
```

`CREATE USER` — это то же самое, что роль с правом входа; в логах может отображаться **`CREATE ROLE`**.

`ENCRYPTED PASSWORD` в современных версиях обычно не обязателен: пароль хранится в виде хеша по умолчанию.

### 8.2. Если база уже создана отдельно

```sql
CREATE DATABASE имя_базы;
CREATE USER имя_пользователя WITH PASSWORD 'надёжный_пароль';
GRANT ALL PRIVILEGES ON DATABASE имя_базы TO имя_пользователя;
```

Владелец базы при этом может остаться тем, кто выполнил `CREATE DATABASE` (например `developer`). Пользователь с `GRANT ALL ON DATABASE` может подключаться к базе, но для **создания объектов** в схеме `public` в PostgreSQL 15+ часто нужно дополнительно (под суперпользователем или владельцем базы, **уже подключившись к этой базе**):

```sql
\c имя_базы
GRANT ALL ON SCHEMA public TO имя_пользователя;
```

При необходимости — права на уже существующие таблицы и объекты по умолчанию; для пустой базы часто достаточно `GRANT ALL ON SCHEMA public`.

Список ролей:

```sql
\du
```


## 9. Быстрая шпаргалка команд `psql`

| Команда | Действие |
|---------|-----------|
| `\l` | список баз |
| `\c имя` | переключить базу |
| `\dt` | таблицы в текущей схеме (часто `public`) |
| `\d имя` | структура таблицы |
| `\du` | роли |
| `\conninfo` | параметры текущего подключения |
| `\q` | выход |
